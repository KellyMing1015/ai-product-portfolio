# Arcana

**以塔罗为入口，探索有性格、有记忆的 AI 互动体验。**

Arcana 是我从个人需求出发、设计并持续迭代的 AI 塔罗网页产品。我把抽牌互动、AI 解读、持续追问与长期记忆串成完整的使用流程，希望用户既能体验抽牌的仪式感，也能在交流中感受到鲜明的表达风格和对话的延续。

在这个项目中，我把产品构思、需求拆解、交互体验和视觉方向落实到可实际操作的应用，并围绕 AI 如何回应、如何记忆、如何接受用户纠正持续打磨细节。

[在线体验 Arcana](https://arcana.ououm.com)

## 我想做出怎样的体验

现在的AI塔罗，几乎都停在"抽牌 → 解读"这一步。用户问一个问题，拿到一段解读，对话就结束了。下一次来，AI不知道她上次在担心什么，也不知道那张牌后来有没有应验。但真正的塔罗咨询从来不是一次性的。一位好的塔罗师会记得来访者，会在下一次见面时问一句"上次说的那件事，后来怎么样了"。

我想做的是一位会记得你的AI塔罗师。他记得你每次抽到的牌和当时的心事，能看出你反复在问同一类问题，在你再来的时候接上你的故事，不用从头讲起。解读也不只是复述牌义，而是回应你此刻的情绪，再解读，必要的时候也会说你不想听的话。

牌是入口，被理解才是人们来抽牌的真正原因。我希望Arcana不只是一个解读工具，而是一段可以持续下去的咨询关系。

## 从一个问题，到一段完整对话

**提出问题 → 长按洗牌 → 滑动切牌 → 抽牌 → AI 解读 → 继续追问**

- **沉浸式抽牌：** 月蚀、星空与牌面构成统一的视觉氛围，支持电脑和手机操作。
- **多种解读方式：** 支持单牌与牌阵，三牌阵可根据问题意图选择适合的解读框架。
- **连续追问：** 在同一副牌下继续交流，结合原问题、牌面和新信息回应。
- **账号与历史：** 保存牌局与个人资料，方便回顾此前的问题和解读。
- **可管理的记忆：** 将持续处境整理为便签，用户可以查看、修改和删除。

## 核心迭代：从流水账式便签到长期记忆

### 在自用中发现问题

早期使用 Arcana 时，我最不满意的是历史便签像流水账：对话中的信息被不断记下来，却缺少对持续处境和当前状态的整理。随着记录增加，重复内容和旧状态也会影响后续使用。

我由此重新梳理了记忆功能的目标：帮助下一次对话快速理解用户当前的处境，并让用户能够管理这些背景。

### 研究开源方案，再转化为适合产品的规则

我阅读了其他开源项目中的记忆设计与实现，结合 Arcana 的连续对话场景，重新设计便签的组织和更新方式：

| 需要解决的问题 | 这次迭代的设计 |
| --- | --- |
| 同一件事分散在多条记录里 | 按主题聚合，合并重复信息 |
| 所有细节平铺，重点不清楚 | 分成核心摘要与补充详情，界面默认展示摘要 |
| 事情有了进展，旧状态仍被保留 | 用明确的新进展更新同一主题的状态 |
| 旧信息被当成当前处境 | 加入确认日期和时效规则，较久未提及的背景提示需要确认 |
| 用户改过的内容可能被旧对话覆盖 | 保留用户纠正依据，并对编辑和删除设置保护 |

这次调整同时涉及记忆如何提炼、如何保存、怎样展示，以及何时带入下一轮对话。我把“什么值得记、什么时候更新、记错之后怎么办”拆成具体的产品规则，让记忆能够随使用过程持续整理。

### 用具体对话检查设计是否生效

验证围绕旧便签整理、新进展替换、重复确认和用户纠正事实保留等场景展开。项目的便签升级记录使用虚构对话、临时数据库和真实模型调用检查这些机制，并根据输出进一步收紧规则。

迭代后的便签以“摘要 + 详情”展示持续背景，支持按新进展更新，也允许用户直接编辑和删除。我把自用中发现的不满，转化为一组能够实现、检查并继续改进的产品设计。

## 对话与使用体验

### 让 AI 在不同阶段，承担不同的对话任务

首次解读需要展开判断、解释牌面；进入追问后，用户更需要对自己刚刚说的话得到回应。

围绕这两种需求，Arcana 将共用人格、首次解读和后续对话分别组织：保持表达风格一致，同时调整回复的篇幅、节奏和关注点。追问可以从牌面延伸到用户补充的真实处境，新的信息也可以改变此前的判断。

我的设计重点是让每个阶段的回答贴合当下的交流目的，让用户愿意把话继续说下去。

### 把等待、中断与恢复也纳入体验设计

一次完整体验还包括等待回答、网络波动，以及中断之后如何继续。

Arcana 对追问断线增加了状态核对：如果服务器已经完成回答，就取回原回答；符合条件时再有限重连，减少重复生成和上下文混乱的机会。牌面图片也按显示尺寸提供较小版本，并在动画中限制等待图片的时间，照顾手机与慢网环境下的使用过程。

我希望这些细节共同支撑用户对产品的信任：操作之后有反馈，出现问题时能够理解并继续。

## 持续迭代方向

- 通过更多真实使用场景，打磨首次进入、完成抽牌与继续追问的流程。
- 继续完善记忆的相关性与时效，让背景信息更准确地服务当前交流。
- 围绕对话风格、使用节奏与用户控制，完善这段 AI 互动体验。

## 技术实现

前端使用 HTML、CSS 和 JavaScript；后端使用 Python / Flask，使用 SQLite 保存账号与历史数据。模型回复以文字流逐步显示，记忆提炼与对话回复分别配置。
